## 0. Evidence and position on the gap map

Proposal 0001 (networking / the `Http` client) explicitly deferred this design: its future-work list (0001 §7) reads *"a `Uri` type + query-parameter ergonomics (string URLs suffice for v1; a `Uri` type is its own proposal — parsing/normalization is a swamp worth its own review)"*. This proposal is that review.

The [2026-07 stdlib gap review](papers/stdlib-gap-review-2026-07.md) does **not** contain a URI/URL item among its 31 ranked gaps. The nearest entry is item **#3 (Base64 + hex encodings)**, whose motivation mentions `data:` URIs — but that item is about binary↔text *encodings*, not URL parsing, component access, or percent-encoding of URI components; nothing in it covers this proposal's ground. The gap surfaced later, through 0001's own deferral line and through 0002's server-side query accessors (`HttpRequest.Query`/`QueryAll`, 0002 §3.2), whose decode semantics currently have no shared normative home. This proposal extends the gap map.

## 1. What exists today (the substrate this builds on)

Nothing URI-shaped exists anywhere in the stdlib — stdlib §11's deferred-modules list reserves `System.Net`/`System.Net.Http` but does not mention a URI type. What the design builds on (all verified in `Bezel_Standard_Library.md`):

- **`string`** (§9.6) — `Split`, `IndexOf`/`IndexOf(value, startIndex)`, `Substring`, `ToLower`, `StartsWith`, ordinal equality; today's URL handling is entirely this, by hand.
- **`Encoding.UTF8`** (§3.2) — the defined-fault byte↔string conversion percent-decoding rides on: ill-formed UTF-8 raises `FormatException`, never a replacement character. Percent-decoding inherits this model wholesale.
- **`FormatException`** — language-built-in (spec §31.4), no import required; the parse-failure fault of `DateTime.Parse`, `Guid.Parse` (§2.5, §2.6) and of `Base64.Decode` (proposal 0009 D3).
- **`ArgumentException` / `ArgumentOutOfRangeException`** — the constructor-validation family (spec §31.4; stdlib §2.5's `DateTime` component validation).
- **The Try convention** (§1) — shapes (a)–(d); §5 below picks the shape with reasons.
- **Consumers waiting on this type**: 0001's client (string URLs, `baseAddress` resolution, redirect `Location` handling), 0002's server (`HttpRequest.Path`, `Query`, `QueryAll`), and 0007's substrate (`Dns` host inputs).

## 2. Motivation: concrete workloads

Every workload below is a service/tool pattern that today requires hand-rolled string surgery, and each has a well-known failure mode the type closes:

1. **Composing API URLs.** `$"{base}/users/{name}?q={term}"` is an injection bug factory: an unescaped `/`, `?`, `&`, `#`, or space in `name`/`term` silently changes the request's meaning. `AppendPathSegment`/`WithQueryParameter` encode by construction.
2. **Redirect handling.** A `Location` header may be absolute, scheme-relative, absolute-path, or relative; resolving it against the request URL is RFC 3986 §5.2, which 0001's client must implement internally for `RedirectPolicy.Follow`. `Uri.Resolve` makes the same algorithm available to user code (manual-redirect mode, crawlers, proxies) and pins one shared behavior.
3. **Endpoint configuration.** Services parse endpoint URLs from config at startup; `Uri.Parse` fails fast with a precise `FormatException` instead of a malformed request minutes later.
4. **Allow-lists and SSRF defense.** "Is this webhook target on an allowed host?" requires case-normalized scheme/host comparison; string `Contains`/`StartsWith` checks are the classic bypass vector (`https://allowed.example.com.evil.net`). Component access makes the check structural.
5. **Cache keys and crawler dedup.** `HTTP://Example.COM/%7eann` and `http://example.com/~ann` are the same resource; normalized component equality (§4's D3) deduplicates them; ordinal string comparison does not.
6. **Server-side query parsing.** 0002's `Query`/`QueryAll` need one specified decode (pair splitting, `+`, `%XX`); `Uri.ParseQuery` is that specification (D6; the compatibility seam is stated in §10).

## 3. D1 — Value record, not class

**Decision.** `Uri` is an immutable **value record** (spec §9): parse once, hold components, no identity, no disposal.

**Rationale.** A URI is immutable value data — exactly the `Guid`/`DateTime` category (§2.5, §2.6), not a resource. A class would impose the ownership regime (`owned Uri` returns, `using var` at every call site) on a type with nothing to dispose, and would put reference equality where users universally expect value equality. As a record:

- **No disposal ceremony.** `var u := Uri.Parse(s);` — no `using var`, no `owned` marker on any `Uri`-returning signature (stdlib §1 conventions: value returns are unmarked).
- **Sendable.** The components are `string`/`string?`/`int?` — reference-typed fields of runtime-managed type do not make a record borrow-bearing (spec §9.7), so `Uri` is **sendable** (spec §30.14, value-type rule) and crosses domains as a copy. A parsed endpoint can be a spawn argument or a channel message; 0002's worker domains can receive request URLs as values. A class-shaped `Uri` would need the §30.14 transfer-closed analysis and `owned` handoff instead.
- **Structural equality for free**, over the normalized components (D3), via auto-equality (spec §9.2) — the cache-key/dedup workload's requirement.

**Where the components live.** The record's storage is exactly the **seven normalized components** of D3 — scheme, user-info, host, port, path, query, fragment — held in **private auto-property storage**; the public component accessors of §8 are computed reads of that storage. Two consequences, both deliberate:

- **Equality and hashing are component-wise over the normalized storage** (auto-equality, spec §9.2 — every component type is admissible: `string`, `string?`, `int?`). `ToString` is overridden to render the recomposed URI (§9.2: a `ToString` override alone suppresses only the auto-`ToString`; auto-equality remains).
- **`with` is unavailable on `Uri`.** A `with` target must be accessible at the use site under the member's own accessibility (spec §9.5), and `Uri` exposes no public storage — so there is no way to replace a component while bypassing parse-time validation and normalization. Constrained update goes through the `With*`/`AppendPathSegment` family (§8), which is precisely §9.5's own guidance: *"a named method for constrained updates rather than relying on `with`."* (The invariant this protects: **every reachable `Uri` value is valid and normalized** — which is what makes D3's equality meaningful.)

One recorded cost: `default(Uri)` is a compile error (spec §17.11 — `Scheme` and `Path` are non-nullable `string` fields), so `Uri` cannot satisfy `where T: new()` and cannot use Try shape (c). §5 takes this into account.

## 4. D2/D3 — RFC 3986, strict, normalized at parse

### D2 — The parsing model: RFC 3986, not WHATWG

**Decision.** `Uri.Parse` implements **RFC 3986** (URI: Generic Syntax): input must be a syntactically valid absolute URI; anything else raises `FormatException`. No error-tolerant fixups, no auto-percent-encoding of stray characters, no scheme special-casing.

**Considered and declined — the WHATWG URL Standard** (full reasoning in §7#1): WHATWG is a browser-compatibility *algorithm*, not a grammar — its goal is to accept what address bars accept (spaces, unescaped `|`, `\`→`/` in special schemes, tabs/newlines stripped, automatic IDNA) and to mirror twenty years of browser quirks. For a systems language whose recorded stance is strict defined-fault (Encoding §3.2: *"malformed input is a defined fault, never a silent substitution"*; proposal 0009 D3: *"silent tolerance hides data problems"*), silently rewriting invalid input into a valid URL is the wrong default — it is exactly how allow-list bypasses and cache-poisoning divergences (parser A tolerates, parser B doesn't) are built. RFC 3986 is what appears on the wire, what servers parse, and what every non-browser ecosystem (Go `net/url`, curl, HTTP itself via RFC 9110) is specified against.

**Scope consequence:** URIs are ASCII by definition (RFC 3986 §1.2.1); non-ASCII input raises `FormatException`. IRI support and IDNA host encoding are declined for v1 (§7#2) — a caller with an internationalized host encodes it (punycode) before parsing, exactly as it must before putting it on the wire.

### D3 — Normalization happens at parse, once

**Decision.** `Uri.Parse` (and the component constructor, and every `With*` builder) applies RFC 3986 **§6.2.2 syntax-based normalization** eagerly, so a `Uri` value is always in normal form and equality is meaningful. The steps, pinned:

1. **Scheme** lowercased; must match `ALPHA *( ALPHA / DIGIT / "+" / "-" / "." )`.
2. **Host** lowercased (reg-names are case-insensitive, RFC 3986 §3.2.2). An IPv6 literal is accepted in brackets; `Host` stores the address **without** the brackets (they are URI delimiter syntax, not host content); `ToString` re-adds them when the host contains `:`. No canonicalization of the address text beyond lowercasing (RFC 5952 canonical form declined for v1, recorded liftable).
3. **Percent-encoding normalization**: hex digits of every escape uppercased (`%3a` → `%3A`); escapes of **unreserved** characters (`A–Z a–z 0–9 - . _ ~`) decoded (`%7E` → `~`). Escapes of reserved characters are **kept** — decoding them would change meaning (RFC 3986 §2.2).
4. **Path**: dot-segments removed (`remove_dot_segments`, RFC 3986 §6.2.2.3 / §5.2.4). The path is stored in **encoded (wire) form** — a path segment may legitimately contain an encoded `/` (`%2F`), so a decoded path string is lossy; decoded access is per-component via `DecodeComponent`.
5. **Port**: digits only, value 0–65535 (else `FormatException`); leading zeros normalized away numerically; an **empty** port (`http://h:/`) — valid per RFC — normalizes to no port (`Port = null`).
6. **Query and fragment** stored in encoded form, verbatim beyond step 3; `Query`/`Fragment` are `null` when the `?`/`#` delimiter is absent and `""` when present-but-empty (the two are distinct on the wire and stay distinct here).

**Scheme-based normalization is deliberately not performed** (declined, §7#4): no default-port elision (`http://h:80/` keeps `Port = 80` and is **not** equal to `http://h/`), no empty-path→`/` rewriting (`http://h` keeps `Path = ""` and is not equal to `http://h/`). Syntax-based normalization is scheme-independent and provably meaning-preserving; the scheme-based rules require a per-scheme knowledge table and change the component values a caller observes. Callers that want the stronger equivalence apply it explicitly (`EffectivePort`, below, gives them the ingredient).

**Equality consequence (normative examples):**

```
Uri.Parse("HTTP://Example.COM/%7eann")  =  Uri.Parse("http://example.com/~ann")     // true
Uri.Parse("http://example.com/")        =  Uri.Parse("http://example.com")          // false (path "/" vs "")
Uri.Parse("http://example.com:80/")     =  Uri.Parse("http://example.com/")         // false (explicit port kept)
```

## 5. D4/D5 — Absolute-only; the Parse/TryParse shapes; IParsable

### D4 — `Uri` values are absolute; relative references stay strings

**Decision.** `Uri.Parse` requires a scheme: every `Uri` **value** is an absolute URI. A relative reference (`/users/1`, `../a`, `?page=2`, `#top`) is not a `Uri`; it is consumed as a `string` by `Resolve(reference)`, which implements RFC 3986 §5.2 reference resolution against `this` as the base.

**Rationale.** A relative reference has no meaning on its own — no scheme, usually no host; a `Uri` type admitting it would make `Scheme`/`Host`/`EffectivePort` partial on every value, which is .NET's recorded trap (`UriKind.RelativeOrAbsolute`, and the `InvalidOperationException` mines on every property of a relative `System.Uri`). Keeping relative references as strings keeps every accessor total and matches the actual dataflow: relative references arrive as strings (a `Location` header, an `href`, a config fragment) and are useful only at the moment of resolution. A dedicated `UriReference` sum type was considered and declined for v1 (§7#3).

### D5 — `Parse` + `TryParse` shapes (stdlib §1 Try convention)

**Decision.**

```bezel
public static method Parse(s: string): Uri;        // FormatException on invalid input
public static method TryParse(s: string): Uri?;    // shape (b): null iff Parse would raise
```

`TryParse` is **shape (b) — nullable return** — not shape (a) (`bool` + nullable out) and not shape (c) (`bool` + non-nullable value out). Reasons, against each alternative:

- **Shape (c) is unavailable.** The `DateTime`/`Guid`/primitive `TryParse` precedent (§2.5/§2.6/§9) assigns `default(T)` on the false path — but `default(Uri)` is a **compile error** (spec §17.11: a record with a non-nullable reference-typed field — `Scheme: string`, `Path: string` — has no well-defined default). The family precedent cannot be followed mechanically here.
- **Shape (b) over shape (a):** §1's own criterion for shape (b) — *"when null alone is the signal … the payload is statically non-nullable at every instantiation, so a bool would carry no information"* (the `Weak<T>.TryUpgrade` reasoning) — applies exactly: a successfully parsed `Uri` is never null, so the bool of shape (a) is pure redundancy. Shape (b) also composes at the call site: `var u := Uri.TryParse(raw) ?? fallback;`, and ordinary local narrowing (`if u <> null then …`) covers the branchy form with no `out` ceremony.

Per §1's convention, `TryParse` returns `null` **exactly** where `Parse` raises.

### `IParsable<Uri>` conformance (stdlib §2.19): declined for v1

`Uri` does **not** declare `IParsable<Uri>`. This mirrors the stdlib's existing posture precisely: `DateTime`, `DateOnly`, `TimeOnly`, and `Guid` all carry `Parse`/`TryParse` as plain static members and are **not** in §2.19's conformance list, and the recorded `bool` reasoning (v0.222, #1792 — quoted in §2.19) transfers verbatim: *the constraint's clients are generic scalar-parsing paths*; a caller that means a URI spells `Uri.Parse` directly; a later admission would be a compatible widening if a generic use case arrives. Declaring conformance now would also force the shape-(a) witness `TryParse(s, out owned value: Uri?)` next to the shape-(b) member — two spellings of the same operation with no client. (The signatures differ in arity, so a later admission does not collide with the shape-(b) member; recorded in §7#6.)

## 6. D6/D7/D8 — Query parameters, module home, faults

### D6 — The query-parameter layer: form-urlencoded conventions, stated plainly

The pair-level query API (`ParseQuery`/`ComposeQuery`/`GetQueryParameter(s)`/`WithQueryParameter`) implements the **`application/x-www-form-urlencoded` conventions** — because that is the convention query strings actually carry (it is how forms, `URLSearchParams`, and every web framework serialize pairs), and it is what 0002's `Query`/`QueryAll` must implement anyway. Pinned:

- **Splitting**: pairs separated by `&`; empty segments (`a&&b`) skipped; a segment without `=` decodes to `(Name = segment, Value = "")`; `=v` decodes to `(Name = "", Value = "v")`. `;` is **not** a pair separator (WHATWG removed it in 2021; RFC 3986 never blessed it).
- **Decoding**: `+` decodes to space, then percent-decoding; applied to names and values alike.
- **Encoding**: space is emitted as `%20`, never `+` — `%20` is unambiguous under *both* the form-urlencoded and the plain-RFC-3986 readings, so a value we compose decodes identically everywhere. Everything outside the unreserved set is percent-encoded (UTF-8 bytes, uppercase hex).
- **Faults**: a malformed escape (truncated, non-hex digits) or an escape sequence decoding to ill-formed UTF-8 raises `FormatException` (the Encoding §3.2 model; strict per 0009 D3). Inside an already-parsed `Uri` the malformed-escape case is unreachable (D2's grammar already rejected it); it is live for the static `ParseQuery(s)` over arbitrary strings.

The pure RFC-3986 component operations — no `+` handling, no pair structure — are the separate statics `EncodeComponent`/`DecodeComponent`, so both layers exist and neither is smuggled into the other. `EncodeComponent` encodes everything outside unreserved (stricter than JS `encodeURIComponent`, which additionally passes `!'()*` — ours is safe in every component position).

### D7 — Home: auto-imported `System`

`Uri` and `QueryParameter` live in **`System` (auto-imported)**, in the value-vocabulary cluster with `Guid` (§2.6) — proposed §2.21, after `Result<T, E>` (§2.20). Reasons: it is a pure value type with no I/O and no native resource, so auto-import carries no side-effect cost (the 0012 Q2 reasoning for `TimeZoneInfo`); its consumers are not only networking (config, logging, CLI tools, build tooling); and placing it below `System.Net` would invert the layering — 0001/0007 should be free to *reference* it, not own it. **`Uri` is deliberately not a §1 intercept point**: parsing and recomposition are pure computation with no world-reads.

### D8 — Fault taxonomy

No new exception types. The complete fault surface:

| Operation | Fault | When |
|---|---|---|
| `Parse`, `Resolve`, `ParseQuery`, `DecodeComponent` | `FormatException` (built-in, spec §31.4) | syntactically invalid input, malformed escape, escape decoding to ill-formed UTF-8 |
| `TryParse` | *(none)* | returns `null` exactly where `Parse` raises |
| component constructor, `With*`, `AppendPathSegment` | `ArgumentException` (with `paramName`) | a component that fails its grammar production (e.g. a scheme with a space) |
| component constructor, `WithPort` | `ArgumentOutOfRangeException` | port outside 0–65535 |
| `EncodeComponent`, `ComposeQuery`, `ToString`, all component reads | *(never fault)* | total functions |

The parser/constructor split follows the stdlib's own precedent exactly: parsers raise `FormatException` (`DateTime.Parse`, `Guid.Parse`, `Base64.Decode`), constructors validating components raise the `Argument*` family (`DateTime`'s component constructor, §2.5). A .NET-style `UriFormatException` subtype is declined (§7#5): no stdlib parser has a producer-specific `FormatException` subtype, and no handler distinguishes "bad URI" from "bad input" by type — the message carries the position and reason.

## 7. Considered and declined

1. **The WHATWG URL Standard as the parsing model.** Declined — full reasoning in D2. Summary: an error-tolerant browser-compat algorithm (auto-encoding of invalid characters, `\`→`/`, tab/newline stripping, automatic IDNA, special-scheme tables) contradicts the stdlib's strict defined-fault model (Encoding §3.2, 0009 D3) and is the raw material of parser-differential vulnerabilities. Interop note: any URL produced by a WHATWG-conforming serializer is a valid RFC 3986 URI and parses here; only WHATWG's *input tolerance* is rejected. Revisiting requires evidence of a real corpus of must-accept browser-shaped inputs, and the remedy would be an explicit lenient entry point (`Uri.ParseLenient`), never a change to `Parse`.
2. **IRI / IDNA (non-ASCII) support.** Declined for v1: IDNA requires Unicode mapping tables with a real bundle-size cost (the 0030 normalization-table discussion is the precedent for weighing this) and a policy choice (IDNA2008 vs transitional) that deserves its own review. The declared behavior — non-ASCII input is a `FormatException` — is forward-compatible with a later `Uri.ParseIri` or an IDNA encoder in `System.Text`.
3. **A `UriReference` type (or .NET's `UriKind`) admitting relative values.** Declined for v1 — D4's reasoning: partial accessors on every value vs. total accessors plus `Resolve(string)`. Revisit if evidence shows string-typed relative references cause real defects that a typed wrapper would catch.
4. **Scheme-based normalization** (default-port elision, empty-path→`/`). Declined — D3's reasoning: requires a per-scheme table and changes observed component values; syntax-based normalization alone keeps `Parse` scheme-independent. `EffectivePort` exposes the default-port knowledge explicitly instead.
5. **A `UriFormatException` subtype.** Declined — D8's reasoning.
6. **`IParsable<Uri>` conformance in v1.** Declined — §5's reasoning; recorded as a compatible future widening.
7. **A mutable `UriBuilder` class.** Declined: a builder class buys mutation ergonomics at the price of the ownership regime (owned instance, disposal, non-sendable) and a second type; the record's `With*`/`AppendPathSegment` family covers construction and modification with values throughout. Revisit only with evidence of builder-shaped hot paths where record re-validation measurably matters.
8. **`Host` as non-null `string` + `HasAuthority: bool`.** Considered for `!`-free ergonomics in the dominant HTTP case; declined: it splits one fact (authority absent) across two members and departs from the stdlib's nullable-for-absence idiom (Guide 2 §5; 0001 §3.2's recorded reasoning). The nullable form also keeps `""` (authority present, empty host — `file:///x`) distinct from null (no authority — `mailto:`) with no extra member.

## 8. Proposed API surface

All types below are **new** (module `System`, auto-imported). Signatures follow the stdlib §1 conventions. No member is marked `pure`: the encode/decode statics build their results through surfaces §22.15's closed list rejects or that are not `pure`-declared today (owned-class-returning calls like `Encoding.GetBytes`, string enumeration under rule 5) — the 0068 §5 posture — so purity marking is left to the docs-editor purity pass (the 0062 precedent).

```bezel
/// One decoded query pair. A two-string value record — sendable (§30.14),
/// the HeaderEntry precedent (proposal 0001 §3.4).
public record QueryParameter(Name: string, Value: string);

/// An absolute URI in RFC 3986 normal form (see D3). Immutable value record;
/// equality is component-wise over the normalized components. Sendable.
public record Uri: IEquatable<Uri>
  // ── construction ──
  // Component constructor: validates and normalizes each component (D3).
  // ArgumentException (with paramName) on a component failing its grammar;
  // ArgumentOutOfRangeException on port outside 0..65535.
  // `host := null` constructs an authority-less URI (e.g. mailto:, urn:).
  public constructor(scheme: string, host: string?, port: int? := null,
                     path: string := "", query: string? := null,
                     fragment: string? := null, userInfo: string? := null);

  public static method Parse(s: string): Uri;        // FormatException on invalid input (D2/D3)
  public static method TryParse(s: string): Uri?;    // Try shape (b): null iff Parse would raise (D5)

  // ── components (normalized; see D3 for each component's stored form) ──
  // Storage is these PRIVATE auto-properties — the §9.2 equality components
  // (D1/D3). Outside the type they are not nameable, so no public `with`
  // target exists and parse-time validation cannot be bypassed (§9.5:
  // `with` copies auto-property storage; the public accessors below are
  // expression-bodied computed views, never `with` targets and never
  // equality components) — constrained update goes through the With* family.
  private readonly property _scheme: string;
  private readonly property _userInfo: string?;
  private readonly property _host: string?;
  private readonly property _port: int?;
  private readonly property _path: string;
  private readonly property _query: string?;
  private readonly property _fragment: string?;

  public property Scheme: string => _scheme;         // lowercase; never empty
  public property UserInfo: string? => _userInfo;    // null when absent; encoded form
  public property Host: string? => _host;            // null = no authority; lowercase;
                                                     //   IPv6 literals without brackets
  public property Port: int? => _port;               // null when absent; 0..65535
  public property Path: string => _path;             // encoded form; dot-segments removed; "" possible
  public property Query: string? => _query;          // encoded, without '?'; null = absent, "" = empty
  public property Fragment: string? => _fragment;    // encoded, without '#'; null = absent

  // Derived views (computed, like every public accessor above — not storage,
  // not equality components):
  public property EffectivePort: int? => _port ?? DefaultPort(_scheme);
                                                     // Port, else the scheme's registered default
                                                     //   (http 80, https 443, ws 80, wss 443, ftp 21),
                                                     //   else null. Fixed table; additions are
                                                     //   compatible widenings.
  public property PathAndQuery: string => (if _query <> null then _path + "?" + _query else _path);
                                                     // the HTTP request-target (origin-form)

  private static method DefaultPort(scheme: string): int?;   // the EffectivePort table

  // ── recomposition ──
  public override method ToString(): string;         // RFC 3986 §5.3 recomposition of the stored
                                                     //   components; deterministic canonical form;
                                                     //   Parse(u.ToString()) = u for every u

  // ── resolution and builders (each returns a fresh, re-normalized Uri) ──
  public method Resolve(reference: string): Uri;     // RFC 3986 §5.2 reference resolution against
                                                     //   this base; FormatException on a malformed
                                                     //   reference. Accepts absolute and relative
                                                     //   references (D4).
  public method AppendPathSegment(segment: string): Uri;
                                                     // percent-encodes `segment` as ONE segment
                                                     //   (a '/' inside it becomes %2F) and appends,
                                                     //   inserting exactly one '/' separator
  public method WithPath(path: string): Uri;         // replaces Path (validated; dot-segments removed)
  public method WithQuery(query: string?): Uri;      // replaces the raw query (validated); null removes
  public method WithFragment(fragment: string?): Uri;
  public method WithPort(port: int?): Uri;           // null removes the explicit port
  public method WithQueryParameter(name: string, value: string): Uri;
                                                     // appends one pair, encoded per D6; never
                                                     //   replaces existing pairs of the same name

  // ── query pairs (form-urlencoded conventions, D6) ──
  public method GetQueryParameter(name: string): string?;
                                                     // first pair with this (decoded) name, decoded
                                                     //   value; null when absent (*OrNull honesty,
                                                     //   stdlib §5)
  public method GetQueryParameters(): owned Array<QueryParameter>;
                                                     // all pairs, decoded, in order; empty array when
                                                     //   Query is null or ""
  public static method ParseQuery(query: string): owned Array<QueryParameter>;
                                                     // the same decode over a bare query string
                                                     //   (no leading '?'); FormatException per D6
  public static method ComposeQuery(parameters: IEnumerable<QueryParameter>): string;
                                                     // encodes and joins with '&'; "" for an empty
                                                     //   sequence; ParseQuery(ComposeQuery(ps))
                                                     //   round-trips names and values

  // ── percent-encoding primitives (plain RFC 3986; no '+' handling, D6) ──
  public static method EncodeComponent(s: string): string;
                                                     // encodes everything outside unreserved
                                                     //   (A-Z a-z 0-9 - . _ ~); UTF-8, uppercase hex;
                                                     //   never faults
  public static method DecodeComponent(s: string): string;
                                                     // decodes every %XX escape; FormatException on a
                                                     //   malformed escape or ill-formed UTF-8 (§3.2
                                                     //   model); '+' is left as '+'
end Uri;
```

## 9. Tour by example

```bezel
// Uri and QueryParameter arrive with the System auto-import (D7). One line
// below uses proposal-0001 surface (DRAFT — Http.Get, import System.Net) and
// is labeled; everything else is current stdlib.

// Parse and inspect. Normalization is visible and pinned (D3).
var u := Uri.Parse("HTTPS://Api.Example.COM:8443/v2/%7eann?q=a%20b#top");
Console.WriteLine(u.Scheme);            // "https"
Console.WriteLine(u.Host!);             // "api.example.com"
Console.WriteLine(u.Path);              // "/v2/~ann"      (unreserved escape decoded)
Console.WriteLine(u.PathAndQuery);      // "/v2/~ann?q=a%20b"
Console.WriteLine($"{u}");              // canonical recomposition via ToString

// Build an API URL safely — no manual escaping, no injection.
var endpoint := Uri.Parse("https://api.example.com/v2")
    .AppendPathSegment("code search")             // → /v2/code%20search
    .WithQueryParameter("q", "a&b=c")             // → ?q=a%26b%3Dc
    .WithQueryParameter("page", "2");
using var resp := await Http.Get(endpoint.ToString());   // proposal-0001 surface (draft),
                                                          //   v1 string form unchanged (§10)

// Allow-list check — structural, not substring (SSRF defense).
public method IsAllowedTarget(raw: string, allowedHost: string): bool
  var u := Uri.TryParse(raw);
  if u = null then
    return false;                       // invalid input is a decline, not a fault
  end;
  return u.Scheme = "https" and u.Host = allowedHost.ToLower();
end IsAllowedTarget;

// Manual redirect handling (RedirectPolicy.Manual, 0001 §3.5): resolve the
// Location header against the request URL — RFC 3986 §5.2, shared with the
// client's internal Follow logic.
var next := current.Resolve(location);

// Read query pairs (decoded, ordered).
using var ps := u.GetQueryParameters();
for var p in ps do
  Console.WriteLine($"{p.Name} = {p.Value}");
end;
```

## 10. Ownership, sendability, and the compatibility posture toward 0001/0002

**Ownership.** `Uri` and `QueryParameter` are value records: no `owned` markers on any `Uri`/`QueryParameter` return or parameter (stdlib §1). The only owned surface is `GetQueryParameters`/`ParseQuery` returning `owned Array<QueryParameter>` — `Array<T>` is a class; the caller disposes (the `Guid.ToByteArray` shape, §2.6). `ComposeQuery` borrows its `IEnumerable<QueryParameter>` for the call (synchronous — no §30.1 borrow-across-suspension question arises).

**Sendability.** `Uri` and `QueryParameter` hold only `string`/`string?`/`int?` components: not borrow-bearing (spec §9.7 — runtime-managed reference fields are exempt), hence **sendable** (spec §30.14) — legal as spawn arguments and channel elements, crossing as copies. This is stated as part of the contract, not an accident.

**Serialization** is deferred: `Uri` declares neither `ISerializable` nor `IDeserializable` in v1. Declaring the §9.8 structural synthesis now would pin a seven-field components object as the wire form; the right wire form is the canonical recomposed **string** (like `Guid`'s "D"), which requires the compiler-provided-conformance mechanism of proposal 0010 — `Uri` should ride that train when it lands, and is recorded there as a candidate.

**Compatibility with 0001/0002 — the posture, explicitly.** The string-URL v1 surfaces of 0001 (client) and 0002 (server) are **frozen; nothing in this proposal changes them**. `Uri` layers *under* them:

- **Adoption is additive, and works day one with zero 0001 changes**: `ToString()` renders the exact wire form, so `Http.Get(endpoint.ToString())` (or interpolation) is the v1 bridge. Later, `Uri`-typed overloads (`Http.Fetch(url: Uri, …)`, `HttpClient(baseAddress: Uri)`, a `Uri`-typed companion to `HttpResponse.Url`) are compatible widenings — new overloads beside the string forms, never replacements.
- **Shared-algorithm seams, to be pinned at those proposals' graduation:** (i) `HttpClient`'s `baseAddress` resolution ("resolves against baseAddress", 0001 §2) and `RedirectPolicy.Follow`'s `Location` handling should be specified as RFC 3986 §5.2 — i.e. behaviorally identical to `Uri.Resolve` — so client behavior and the public type never diverge; (ii) 0002's `HttpRequest.Query`/`QueryAll` should be specified as "per `Uri.ParseQuery`" (D6's decode), giving the server-side accessors their currently-missing normative decode. The 0001 seams are notes on a *draft*; the 0002 seam **amends an accepted design** (0002 was accepted 2026-07-24 by delegated ruling) and is therefore raised as open question 6 rather than assumed.

## 11. Open questions for the owner

1. **Home module** — auto-imported `System` (§2.21, beside `Guid`) is proposed (D7). Confirm, or prefer `System.Net` (making 0007 a prerequisite and requiring an import at every non-network use site)?
2. **`+`-as-space at the pair layer** (D6) — the form-urlencoded conventions are proposed for `ParseQuery`/`GetQueryParameter(s)` because that is what deployed query strings carry; the strict-RFC alternative (treat `+` as a literal) is available via `DecodeComponent`. Confirm the pragmatic split, or require strict-RFC at the pair layer too?
3. **`EffectivePort` table** — `http/https/ws/wss/ftp` proposed. Confirm the set (additions are compatible widenings), or drop the property and leave default-port knowledge to callers?
4. **`TryParse` shape** — shape (b) is argued in D5; the alternative shape (a) (`TryParse(s, out value: Uri? when true): bool`) would keep the spelling parallel with the value-type `TryParse` family at the cost of a redundant bool. Confirm shape (b)?
5. **`UserInfo` in rendered output** — `ToString` includes user-info verbatim (it is part of the URI). A redacting render for logs (`ToString` variant or a logging-side rule) is deferred; flag now if credentials-in-URL handling should be v1 surface.
6. **The 0002 amendment (§10)** — specifying 0002's `HttpRequest.Query`/`QueryAll` as "per `Uri.ParseQuery`" amends an **accepted** design. Approve routing that amendment through 0002's graduation, or leave 0002's decode unspecified until a separate ruling?
