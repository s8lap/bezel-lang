## 0. Thesis

Trivial-dispose today bundles two separable exemptions:

- **The ceremony exemption.** No `using var` needed, no must-use warning, `_ := expr;` cosmetic. This is what v0.61 and v0.66 argued for, what rationale §5.9 records, and what every user-facing surface of the feature teaches.
- **The tracking exemption.** References to trivial instances may outlive any statically-known bound; memory is reclaimed by an unspecified runtime mechanism ("reference counting, region allocation, or another scheme", §28 preamble). This is what makes abandonment and two specific carve-outs sound — and it is the *only* reason any runtime lifetime machinery for user classes needs to exist.

**This proposal keeps the first exemption verbatim and retracts the second.** Every trivial-dispose instance gets exactly one statically-known owner at every point (the K1 classification it already carries); the compiler inserts a *free* — logical disposal plus reclamation, running no user code — at that owner's release point. Nested collection literals, the tracking exemption's one real ergonomic pillar, are preserved by a new **literal-tree ownership rule** (§3). The runtime-managed trio (`string`, boxed values, function values) is out of scope and unchanged.

The payoff: **no runtime lifetime mechanism exists for user classes at all** — no counts, no atomics, no cycle policy, no "not a GC in the sense Bezel avoids" hedging for them. The no-GC claim becomes unconditional for every class the user can write. The Rust comparison in rationale §1 sharpens into fact: ceremony-free simple classes were never the thing that cost a mechanism; un-tracked references were.

## 1. The current state, precisely

### 1.1 What the docs actually say

The docs audit found **no single stated "tracking exemption."** What exists decomposes into:

1. **K1.6** (§28.3, line 6216): trivial instances carry the ownership classification, "but their obligation's content is empty, so discharge is not demanded of the program."
2. **The mechanism sentences** (§28 preamble line 6104; §28.9 lines 7051/7055; §17.13 line 3456; the v0.184 borrowing-collections echoes at 6123/7156/7183/7194; stdlib §4.4 line 1563): memory lifetime is decoupled from any tracked owner.
3. **Exactly two explicit static-checking carve-outs**: §15.4's fresh-trivial-producer-in-borrowing-literal admission (line 2772), and §22.5's trivial default on a plain parameter (lines 4466/4485).

Everything else in the ownership chapter is type-agnostic and already tracking-shaped: the producers table, the static-return rule, the borrow-escape rules, §28.11's store rule, the consume-site freeze, K8 boundaries, and the closure-capture bounds apply to trivial-typed references by their letter. **The docs are internally split**: §9.7 (line 1395) rejects `new Bag([10, 20, 30])` on the ground that the literal "has a lifetime that ends at the construction expression" — a statement only true under silent tracking, in tension with the mechanism sentences. This proposal resolves the split in §9.7's favor. Seven further sites are genuinely ambiguous (the current text does not decide the question tracking forces); §5 resolves them.

### 1.2 What the implementation actually does

The implementation audit's verdict: **bezelc is already a silent-tracking implementation in architecture, and contains zero infrastructure for the runtime-managed alternative.**

- **Sema.** Every class-typed `new` is classified Owned regardless of trivial-dispose (`producerState`, `src/ownership/Ownership.cpp:3385-3422`); every borrow-escape channel rejects trivial references outliving their source. Probe C — a scope-local trivial `Box` `Add`ed into an enclosing-scope `Array<Box>` — is a compile **error** under the §28.11 store rule. The general trivial carve is explicitly parked as NOT-YET-DECIDED at the one trivial-adjacent relaxation that contemplated it (`Ownership.cpp:774-788`, #2332). One divergence runs *opposite* to the spec: the §28.3 must-use warning fires on trivial `new` locals, which §28.9 line 7053 forbids (#2654).
- **Runtime.** `bezel_runtime_refcounting.cpp` covers strings, closures, and boxes — plus the static-owned atexit registry and an identity-hash side table. There is no count, registry, arena, or deferred-reclaim structure for user class instances anywhere. Instances are `calloc`'d and freed by codegen-emitted code.
- **Codegen.** Bound shapes free at statically-known points (probes: plain-var auto-drop, `using var`, and user-class `_ := new Box();` are all LSan-clean). The abandonment surface is a patchwork with holes, each a silent leak (#2655): bare `new Box();` leaks 16 B with zero diagnostics; `_ := new StringBuilder();` — the spec's own §17.13 example — leaks 552 B; fresh trivial literal elements (`[new Box(), new Box()]`, spec-admitted at C.3) leak 32 B. The nested `Dictionary<string, Array<int>>` literal — §15.4's own motivating example — **fails to lower entirely** (#2660; the ICE's `#1386` tag names the closed null-guard hardening sweep that added the diagnostic, not a live tracker). The flat literal/materializer reclaim family (#1871/#2142/#2143) is a compile-time escape analysis with a deliberate "leak, the safe direction" posture on escape (`LlvmBackend_Setup.cpp:17252-17257`).

In short: the spec's runtime-managed model was never built. What exists is a slightly-incomplete silent-tracking system whose gaps are all leaks and an ICE. This proposal aligns the spec with the implementation's architecture and turns the gaps into defined obligations.

## 2. The proposed rule

**Silent tracking.** For every trivial-dispose class instance:

1. **Ownership is tracked exactly as for any class** — the K1 classification the instance already carries, now load-bearing. The statically-known release points are the existing ones: scope end for locals and `using var`; end of full expression (K8) for unbound temporaries; drop-on-overwrite for reassignment; the containing object's teardown for `owned` fields; process exit for statics; after the matching catch arm for throw operands; frame teardown for frame-held values.
2. **The compiler inserts the free** at the owner's release point. The free is **logical disposal followed by reclamation**: it sets the per-instance disposed flag (§28.2) and runs no user code (the class has none to run). Riding the flag means checked disposal mode backstops every trivial-instance dangle as a deterministic `DisposedAccessException`, exactly as for non-trivial classes — without this clause the retraction would create the language's only un-backstopped dangling class, so it is a **mandatory companion**, not an option (§28.2/§28.12 amendments). Its cost, stated: trivial instances carry the per-instance flag word, member access through a borrow becomes a live flag test in checked mode, and §28.12's quarantine defers their physical reclamation — checked-mode-only costs; unchecked builds pay nothing (§28.2's existing posture).
3. **The ceremony exemption is retained verbatim.** No `using var` needed, no must-use warning (K1.6 rewrites to: the obligation's *user-visible* content is empty and its discharge is never demanded *of the program* — any undischarged trivial value is freed silently at its owner's release point). `_ := expr;` frees at end of statement — identical timing to the non-trivial case, still cosmetic in the sense that no user code runs.
4. **The trio is untouched.** `string`, boxed values, and function values remain runtime-managed (§28.9's list and rationale §4.1/§4.2 stand). Their mechanism is already implemented, small, and closed; nothing in this proposal touches it.
5. **Cross-domain moves transfer the free obligation** (new §30.14 clause): the receiving domain's owner frees the moved instance at its release point; the origin binding is moved-from as usual. No cross-domain bookkeeping exists or is needed — single owner at all times. This deletes what would have been the mechanism's hardest corner (cross-domain reclamation of trivial instances). Trivial-sourced borrows join §30.14's pre-transfer-alias residuals verbatim. The three delivery channels (spawn arguments, task results, channel `Receive`) are covered by the clause directly; the channel-internal disposal sites — undelivered items disposed at the channel's own disposal, and the item disposed by a faulting send (§30.15) — need no separate clause, because item 2's redefinition of disposal for trivial instances covers them; the amendment says so in one sentence.

## 3. The literal-tree ownership rule

The tracking exemption's one real ergonomic pillar is the nested collection literal (`var config: Dictionary<string, Array<int>> := [...]` — §15.4's own examples). The replacement rule:

> **The fresh nodes of a collection literal — nested literal nodes, fresh producer elements (`new` expressions and `owned`-returning calls in element position), and any element expression whose arm-meet classification is owned (a conditional element such as `[(if c then [1] else [2])]` joins the aggregate) — form an aggregate per maximal borrowing-family subtree. Each aggregate is owned by whatever owns its subtree's root: the receiving binding, the K8 temporary, an owning collection's element slot, an `owned` parameter/return through which the container transfers, an `owned` field (the aggregate freed in the containing object's teardown cascade — §5 c1/Q2), or static storage (process exit). The compiler frees the aggregate — all nodes, one obligation — at that owner's release point. Aggregate membership is fixed at construction; borrowed elements (`cached` in `["a": [1], "b": cached]`) are never members and are never freed with it.**

Resolutions of the audited edge cases:

1. **Literal as a call argument** (`ProcessBuffer([1, 2, 3]);`, the §22.14 variadic idiom `Log(["hello", "world"]);`): the aggregate's owner is the K8 temporary, freed at its K8 boundary — statement end in the common case, but per-evaluation in conditions and guards (K8.2, so loop iterations never accumulate aggregates), and the binding atom's or `case` construct's boundary where K8.5/K8.3 apply; the callee's plain parameter borrows call-bounded. Callee retention is the standard unbound-temporary residual — no new trust category. An `owned` parameter takes the aggregate by transfer instead. The variadic idiom survives untouched.
2. **Returned literal** (`return [1, 2, 3];`): legal through an `owned` return — the aggregate follows the container's obligation wherever K3 sends it (the stdlib's own `Build(): owned OwningArray<Connection>` example already has this shape). Through a non-`owned` return: rejected (§5's c3 resolution).
3. **Owning-family boundaries**: an element consumed by an owned ingress position inside the literal leaves the aggregate at construction — the owning collection's cascade owns it. This is why the rule is per *maximal borrowing subtree*, not per outermost literal: in `OwningArray<Array<int>> := [[1, 2], [3]]` the inner fresh nodes belong to the owning slots, and there is no double owner.
4. **Reassignment** (`xs := [3, 4];`): drop-on-overwrite frees the whole displaced aggregate after RHS evaluation. The consume-site freeze applies if any borrow of any node of the displaced tree is live; granularity is **per-aggregate conservative** — a borrow of an interior node (`var inner := groups["primes"];`) freezes the whole aggregate. Cheap, coarse, and revisable later without breaking programs (per-node tracking would only *admit more*).
5. **`Add` after construction is not a literal position** (§4). Aggregate membership never grows.
6. **Field initializers** are the definition-level question, resolved in §5 (Q2).

## 4. The one ergonomics regression: `Add`-position fresh trivial nodes

`groups.Add("odds", [1, 3, 5]);` — incremental construction of nested trivial structures — is ownerless-and-safe today only because of the mechanism. Under silent tracking the argument is an unbound temporary freed at statement end, and the collection would hold a flagged dangle. The recorded choice (recommended: **option i**):

- **(i) Keep the admission uniform.** Fresh trivial arguments to `Add`/`Insert`/indexer-set join the *existing recorded hazard* for non-trivial ones (§15.4's deliberate literal-only-rejection asymmetry, whose reason — "an opaque callee's signature does not announce retention" — is type-agnostic). Checked mode backstops (§2 item 2). Smallest edit, no new rejection surface, consistent with #1813's precedent for tasks.
- (ii) Extend §15.4's literal rejection to `Add`-position fresh trivial producers. Safer but contradicts the recorded reason the asymmetry exists, and rejects today-working code paths the corpus shows people don't actually write.

Either way, **the documented remedy is the owning family**: `OwningDictionary<string, Array<int>>` takes `owned` ingress, so `owning.Add("odds", [1, 3, 5])` is well-formed and correctly owned. The remedy's costs, stated for Q1's record: the type change is one line, but the owning container makes its *binding* non-trivial — one `using var` returns, per container, not per entry — and `OwningDictionary` deliberately has no default entry iteration (iterate `Keys` or `Drain()`, stdlib §4.9). One further Q1 datum: under option (i) with the retained no-warning rule, `groups.Add("odds", [1, 3, 5]);` compiles with **zero diagnostics** while the compiler knows the argument dies at the K8 boundary — a statically-certain dangle emitted silently; if that is unacceptable, option (i) can carry a targeted lint at fresh-trivial `Add` arguments without touching the ceremony exemption (a Q1 sub-choice). §28.3's unbound-temporaries subsection gains one sentence either way: trivial temporaries are freed at the same K8 boundary as non-trivial ones are disposed.

## 5. Resolving the seven ambiguities

The audit found seven sites where the current text does not decide what tracking forces. Resolutions:

- **c1, fresh trivial tree into a plain field** (`private _idx: Array<int> := new Array<int>();`): **require `owned`** — uniform with the fresh-store rule's letter (§28.6 line 6697). This raises the definition question **Q2**: an `owned` field today flips its holder non-trivial, so wrapper types (a user `Counter`-shape) would lose the ceremony exemption for holding what the free-cascade handles without user code. The candidate amendment: **the trivial-dispose definition disregards `owned` fields of trivial-dispose type** (the synthesized cascade still runs no user code, so "provably a no-op `Dispose()`" stays true in the sense that matters). Costs to rule on: the definition is carried in artifact interfaces (§2.8.2), enters the delta classification (§2.8.6's derived-property rows), amends §3.6's own property-table row ("no `owned` fields"), interacts with sendability (§30.14 rule 2 already admits `owned` sendable-class fields, so the Q2 shape is simultaneously trivial-dispose *and* sendable — exactly the composition §2 item 5's moved-obligation clause must carry), and has been stable since v0.61. Fallback if declined: accept the flip (ceremony loss for wrapper types; semantics unharmed).
- **c2, fresh trivial from a getter** (`get => new Random();`): **error**, uniform with axiom A4 — the fresh value's owner would be a call-bounded temporary the caller's borrow outlives.
- **c3, fresh trivial through a non-`owned` instance return**: **error**, uniform with the fresh-value rule (statics already unambiguous — the static-return rule applies to all class types).
- **c4, the kernel silence**: closed by §2 item 1 — the borrow half of the machinery is demanded everywhere; §15.4/§22.5 stop being relaxations of it.
- **c5, Guide 01's "disposal only, never lifetime" sentence**: becomes true without qualification; promoted to the section's thesis.
- **c6, composite trivial-dispose stdlib types** (`Counter<K>`, the sorted forms): their backing is an **intrinsic single-allocation layout fact** — the instance's one free releases it — a compiler-known device users express with `owned` fields (per c1/Q2). Stated in stdlib §1.
- **c7, deferred-activation escapes over trivial temporaries** (`xs.ToArray().Where(p)` unbound): the reject reading is confirmed; flagged for the implementation-conformance sweep, not a spec edit.

## 7. History compatibility

- **v0.61** committed to ceremony relief only ("ownership warnings … reduced to informational severity"). Fully compatible.
- **v0.66** did commit to the mechanism ("Only trivial-dispose classes … get the implementation-defined memory mechanism") — but as the *honesty device* that let option B ("tighten the discard") avoid option A ("embrace runtime-managed class instances… it's GC-shaped"). Silent tracking **completes** that direction: it removes the last mechanism entirely, making "no GC, no runtime lifetime machinery for user classes" unconditional. The changelog entry frames it so; the v0.66 entry is never edited.
- **v0.184** created the nested-literal reliance this proposal replaces (the §15.4 carve-out) and declined "making backing-storage release a real obligation — ceremony on every dropped `ToArray()` result." That decline is **not** reversed: ceremony stays waived; only the free point becomes static.
- **v0.202**'s pure-throw carve-out survives; its recorded future widening (trivial-dispose construction in pure bodies) remains viable — a compiler-freed instance is still effect-free — with its justification restated when taken up.

## 8. Alternatives considered and declined

1. **Status quo + the layered runtime** (escape analysis → arenas; static frees; domain-local RC with elision; atomic promotion at compiler-known domain crossings; cycles leak with tooling). Workable and previously sketched — but every layer except the first two must be *built* (the audit: zero exists), the cycle policy and the "not a GC" hedging never go away, and the owner's objection stands: it is a hidden per-type runtime purchased for a feature whose value is ceremony, which the retraction delivers without any of it.
2. **Restricting trivial-dispose to provably acyclic types.** Declined for non-locality: acyclicity is a property of the global type-reference graph ("can anything I reach, reach me"), not of a type's own declaration — either non-modular (a private field addition in one module flips classifications in another) or brutally conservative (every `Object`/interface field assumed cyclic, reclassifying the tier's most valuable inhabitants). Breaks §3.6's stated basis that a derived property is "computed from the type's *structure* — its declaration and, for a generic type, its type arguments": a global type-reference-graph property is computed from *other* declarations.
3. **Uniform loud ceremony** (all classes tracked *and* warned). Declined by the recorded v0.61→v0.66 history: the warning had no content then and has none now. Silent tracking is precisely this option minus the noise.
4. **A declared opt-out marker** (or the empty-destructor idiom) letting performance-sensitive classes exit the mechanism. Solves nothing structural — the mechanism must still exist for everyone else — and adds an axis. Subsumed: under silent tracking there is nothing to opt out of.

## 9. Migration, test impact, and staging

**Corpus.** The docs audit found the example corpus *nearly clean*: every doc example already binds its trivial trees (`using var`, `owned` fields), and **no normative example stores a fresh trivial instance through an escaping borrow**. The breakage lives in rules, not examples. The shapes that change status: §15.4's nested literals (saved by the literal-tree rule — they are its motivating corpus); the call-argument and variadic literals (saved by edge case §3.1); `coll.Add(new Trivial())` (the §4 choice; remedy per §4, costs stated there); `return [1,2,3]` (legal only through an `owned` return — §15.4 line 2747 gains the `owned` requirement explicitly, per §5 c3).

**Tests.** Because the ceremony exemption is retained, the acceptance tests survive: #1504's warning-not-error posture, #1684's trivial default (re-derived, same observable), the §22.15 pure family, the #2073 vacuous-pin lint. The reclaim family (#1871/#2142/#2143/#2148) *pins the proposal's own semantics*. Net-new work is mostly **adding** tests: the three leak shapes (#2655), the trivial-variant escape rejections (#2656), the literal-tree aggregate lifetimes, the flag-setting free under checked mode.

**Staging.** Stage 1: the docs revision (everything in §6), gated per the docs process. Stage 2: compiler conformance — the warning gate (#2654), the codegen generalization of end-of-statement reclaim to the abandonment shapes (#2655), the nested-literal lowering fix (#2660), recording #2332's answer, and the new test families. Stage 2's riskiest piece, named by the audit: converting the escape-analysis "leak-not-UAF" posture into frees requires watertight sole-owner proofs — sharpest for literal element temporaries that may also be named borrows in scope — and inherits the project's costliest historical defect class; the aggregate-conservative freeze (§3.4) is chosen partly to keep those proofs simple.

## 10. Questions for the owner

- **Q1** — §4: `Add`-position fresh trivial nodes: option (i) uniform admission as recorded hazard (recommended, **with the targeted lint on**: rejection cannot be scoped by signature — `coll.Add(new X())` and `sink.Consume(new X())` are indistinguishable plain-parameter calls — and the lint is the ceremony exemption's counterpart, restoring a signal at the one shape where silence hides a statically-certain dangle; recorded follow-on: the same lint would serve the non-trivial #1813 shape) or (ii) rejection?
- **Q2** — §5 c1: amend the trivial-dispose definition to disregard `owned` fields of trivial-dispose type (recommended, costs stated), or accept the wrapper-type flip?
- **Q3** — §3.4: per-aggregate conservative freeze granularity (recommended), or demand per-node tracking from the start?
- **Q4** — §9: land stage 2's independent bug fixes (#2654, #2655, #2660) ahead of the stage-1 docs revision, or hold them to ship together? **Recommended: land all three now.** #2654/#2660 are conformance bugs identical under every ruling. #2655's literal-element fix (free the elements with the receiving binding) is a conforming implementation of *both* readings: the literal-tree semantics under this proposal, and a legal choice of the current spec's implementation-defined mechanism — today's sema already rejects every escape, so no accepted program can observe the free, which is the spec's own "invisible to programs" condition. Stage 1 then documents semantics the implementation already exhibits. #2656's escape pin rides the #2654 lane.
