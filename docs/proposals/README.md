# docs/proposals — design proposals (non-normative)

This folder holds the design proposals for Bezel. Nothing here is normative: the language is defined by the documents in `docs/` (the spec, the standard library, the rationale, the guides and the changelog). A proposal graduates by being amended *into* those documents through a spec revision; its file then stays here with a `graduated-v0.NNN` status pointing at the landed revision. How a change is proposed, reviewed and landed is [`spec-change-process.md`](spec-change-process.md).

**Layout.**

- `NNNN-short-slug.md` — one file per numbered proposal. Files never move: their paths are cited from the changelog, the rationale and the issue tracker. A proposal's status changes in place.
- [`DECLINED.md`](DECLINED.md) — the register of every recorded decline, with reasons and reopening bars.
- [`papers/`](papers/) — working papers that are not proposals: audits, currency sweeps, run plans, explorations (indexed under *Working papers* below).
- [`archive/`](archive/) — consumed working papers kept for provenance.

**Status.** Every proposal's `Status` row — in its file and in its row below — leads with a token from the closed set `under-review` / `accepted` / `graduated-v0.NNN` / `declined` / `study`, then ` — `, then the prose record. The section a row sits in follows from its token: `under-review` and `study` under *Pending decision*, `accepted` under *Accepted, awaiting graduation or implementation*, `graduated-v0.NNN` under *Graduated*, `declined` under *Declined*. [`scripts/check_proposals.sh`](../../scripts/check_proposals.sh) checks the file↔row bijection, the token agreement and the section placement.

**Conventions.** Every proposal carries a header block (`Status`, tracking issue, target module(s), the spec revision it was written against). No invented current-stdlib APIs: everything a proposal builds on is cited from `Bezel_Standard_Library.md`, and everything new is marked as proposed, in real Bezel syntax that parses against Appendix A.
