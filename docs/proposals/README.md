# docs/proposals — design proposals (non-normative)

This folder holds **work-in-progress design proposals** for future Bezel features. Nothing in this folder is normative: the language is defined solely by the five documents in `docs/` (spec, stdlib, rationale, and the two guides). A proposal graduates by being amended *into* those documents through the regular docs workflow (revision bump, changelog, mechanical validation), at which point the proposal file gains a `Status: superseded` header pointing at the landed revision.

Conventions:

- One file per proposal, numbered: `NNNN-short-slug.md`.
- Every proposal carries a header block: `Status` (draft / under-review / accepted / superseded / withdrawn), `Tracking issue`, `Target module(s)`, and the spec/stdlib revision it was written against.
- Proposals must obey the repository's cardinal rule: **no invented current-stdlib APIs** — everything the proposal builds on must exist in `Bezel_Standard_Library.md` (cited), and everything new must be clearly marked as proposed.
- Proposed APIs are written in real Bezel syntax and should compile against the grammar (Appendix A) even though the types don't exist yet.
- Every `Status` row — in the proposal file and in its README row below — leads with a canonical status token from the closed set `under-review` / `accepted` / `graduated-v0.NNN` / `declined` / `study` (token, then ` — `, then the prose record); `scripts/check_proposals.sh` mechanically checks the file↔row bijection, the token agreement, and the section placement.

**Status legend & where acted-on proposals go.** The `Status` column of the tables below is the **ledger and the owner-review queue** — the single ground truth for what is settled vs. pending (see [`spec-change-process.md`](spec-change-process.md) §8). The lifecycle: `draft` → `under-review` → `accepted` → (graduates) → `superseded`, with `declined`/`withdrawn` as terminal exits. A proposal that has been **acted on** does *not* leave this folder — it changes status **in place**: an accepted design that graduates into the normative docs gets a `Status: superseded` header pointing at the landed revision (git history is the "archive"); a declined direction gets a one-line entry in [`DECLINED.md`](DECLINED.md) with reasons. Only consumed *non-proposal* working papers move to [`archive/`](archive/). **As of 2026-07-12, the owner-accepted spec-facing proposals have graduated into the normative docs**: **0003, 0032, 0033** in **v0.186** (`3d08ec2`), **0035** in **v0.187** (`7024955`), and **0034, 0036, 0037, 0038, 0039** in **v0.188** (`ebfa7e0`) — each now carries `Status: superseded` pointing at its landed revision. The graduation is docs-only; the compiler catch-up is tracked by the impl issues filed at landing. The earlier `accepted (2026-07-07, delegated)` stdlib proposals (0001/0002/0006–0031) remain stdlib-implementation-wave material and await implementation runs (see [`implementation-roadmap-2026-07.md`](implementation-roadmap-2026-07.md) and [`master-plan.md`](master-plan.md)).
