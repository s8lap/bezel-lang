## 0. Thesis

Two open soundness routes (both flag-backstopped since proposal 0153) remain against the storage bans on a value that holds borrows: the standard library's equality search boxes such a value into a declared `Equals(Object?)` that may store it (#5739, cells R3/C4, R6/C4 route 2, R6/C3·equality, generics R4/C12·eqsearch), and a generic body's `x as T` over a concrete `IReadOnlySpan<TElement>` value reaches `Object` at `T = Object` (#5740, cells R6/C4 route 1, generics R2/C6, R9/C6). Each is one more position of a family that v0.316–v0.333 closed one at a time — a field, an `Object` parameter, a substitution, an `as`, a retyping, a formation, a task result, an event payload, an `async` parameter, a capture — and that has produced a new route at each of four matrix runs.

The question the owner put is which of three postures the language takes:

- **(a)** *A value that holds borrows is a borrow.* Its source set is the union of its carried borrows' sources, and every rule of §28.3 reads it exactly as it reads a class borrow — the same admissions under the same recorded residuals, the same rejections, the same K4.1 backstop (a span reads through its backing object's accessors, §28.2). The per-kind storage bans are retired: both routes close by construction, because a box reaching an `Object` field or a user `Equals(Object?)` is then the field-store residual a class reference already takes there. ≈7,000 words of spec and stdlib become one bullet. Nothing is newly rejected.
- **(a')** (a) plus **one default-build warning**, keyed on the value's kind, at every admission (a) newly makes under a residual — the positions that were compile errors through v0.333 — with the trust-admission report listing the same sites. The owner's question "can a compiler still warn about those incorrect cases?" is answered yes, at zero verdict cost.
- **(b)** The bans kept, and the two routes closed by declaration: `IReadOnlySpan<TElement>` is closed to user implementations (SIMPLIFY C1), a record that holds borrows may not declare `Equals(Object?)` (C5), and an `as` or typed pattern at a type parameter over a span-interface operand is a per-instantiation requirement (#5740 option A). Three small rules, zero measured reach, the posture of v0.332 unchanged.

Every option is sound in checked disposal mode. They differ in the unchecked build's undefined-behaviour surface (b keeps it smaller for value-carried borrows), in text (a removes ≈7,000 words; b adds four sentences), in migration (a and a' flip 21 rule cases, ≈22 lit files and ≈10 gtest programs reject → accept; b flips none), and in how many more routes the family can still produce (a and a' leave none; b keeps the enumeration). The lane drafting this proposal recommended (a'); the critic, deciding under the owner's delegation, chose **(b)** (§5.0), and (a) and (a') do not land.

## 1. Ground truth

### 1.1 The two routes

**Route 1 — the equality search (#5739).** Stdlib §4's *Equality search at an element type with no equality* admits `Contains`, `IndexOf`, `Remove(item)`, `LinkedList<T>.Find`, `Stack`/`Queue.Contains` and the span family's `IndexOf`/`Contains`/`SequenceEqual` "only where the element type, nullability stripped, has a member for the comparison language spec §9.2 calls the first kind, `Equals` with an argument of that type", and withholds it only at "§9.2's, §35.7's or §15.1.2's use-site error" or at §22.6's ambiguity. §9.2 *Through a type parameter*: "At a record … the first kind reaches a record's declared `Equals(T)` where it declares one, and otherwise its declared `Equals(Object?)`"; at every other S "the member the same use on an S-typed operand binds, an inherited `Object` member included". §9.7's borrow-erasing bullet rejects `p.Equals(q)` written at a record's `Equals(Object?)` ("a record's `Equals(Object?)`, which its `Equals(T)` and `=` replace"), but the comparison inside `Contains` runs in a standard-library body, which "contributes no requirement" (§3.6 rule 2). Two faces:

```bezel
class Item public method N(): int => 1; end Item;
class Sink
  private _o: Object?;
  public method Keep(o: Object?)
    _o := o;                         // plain parameter: §28.3's field-store residual admits it
  end Keep;
end Sink;
static class Registry
  public static readonly Sink: Sink := new Sink();
end Registry;
record Pair(Item: Item)
  public override method Equals(other: Object?): bool
    Registry.Sink.Keep(other);       // the T-typed argument arrives boxed at Object?
    return false;
  end Equals;
  public override method GetHashCode(): int => 0;
end Pair;
public static method Run()
  do
    using var it := new Item();
    var ps: Array<Pair> := [new Pair(it)];      // a local collection in it's block: admitted (§9.7)
    var hit := ps.Contains(new Pair(it));       // register: Pair has a first-kind member, Equals(Object?)
  end;                                          // it disposed; Registry.Sink holds a boxed Pair borrowing it
end Run;                                        // `new Pair(it).Equals(p)` written here is rejected (§9.7); via Contains no rule fires
```

The second face is `IReadOnlySpan<TElement>`: the first kind there binds `Object`'s virtual `Equals(Object?)`, nothing closes the interface to user implementations, and a user class implementing `IReadOnlySpan<int>` whose `override Equals(other: Object?)` stores its argument receives a span box from `Array<IReadOnlySpan<int>>.Contains(…)` or a `Set<IReadOnlySpan<int>>` (lane M1's 23-line program, `scratch/matrix/r4/M1.md`).

**Route 2 — `as T` over a concrete span value (#5740).**

```bezel
class Keep<T>
  private _v: T?;
  public method Put(x: IReadOnlySpan<int>)
    _v := x as T;     // x's type mentions no type parameter: §9.7 gives the body no per-instantiation requirement;
  end Put;            // T is not Object or an interface at the declaration; the body is not re-checked
end Keep;
public static method Run(k: Keep<Object>)
  do
    var a: Array<int> := [1, 2, 3];
    k.Put(a.AsSpan());   // admitted: the parameter is declared IReadOnlySpan<int>, and the source outlives the call
  end;                   // a disposed; k._v is an Object boxing a span over it (§12.7: an ordinary run-time test at T = Object)
end Run;                 // `x as Object` written directly is rejected (§9.7)
```

§28.3's *Set-erasing positions* closes the function-value twin at the declaration ("an `as` or a typed-pattern binding whose target is one of the body's type parameters … is a set-erasing position at the declaration"); the span twin is missing. The same escape runs through a chain `Outer<W>` naming `Keep<W>` at `W = Object` (generics R9/C6) and through a dispatched generic method's body.

## 3. Options

### 3.1 The principal options

**(a) — A value that holds borrows is a borrow** (the retrospective review's R5). One new bullet in §28.3's *Borrow lifetime rules*:

> **A value that holds borrows is a borrow (derives: K2.2).** A value of a value type that holds borrows (§3.6) — and a box of one (§8.6), and a value of an interface type such a type implements (`IReadOnlySpan<TElement>`) — is, for every rule of this section, a **borrow whose source set is the union of the sources of the borrows it carries**, read off its components. Every rule that reads a borrow reads it so, with no further rule for the value's kind: the local-scope bullet; the field-store bullet (a parameter-, receiver- or field-path-sourced value admitted under its residual and reported; a scope-bound local's, an `owned` parameter's or a temporary's borrow rejected); the static-store bullet (every carried source static storage, or none — §9.7's null-source form); §28.11's store rule; the callee-side return list; the closure bullet; the consume-site freeze (K5.5); §28.14 (a boxed `scoped` argument's sources tested and frozen); §30.1's settlement clause. The backstop is the one every class borrow has (§28.2). A position declared `Object` or an interface announces no source for a box as for a class reference, and the box carries the same residual there, so there is no borrow-erasing position. A value that carries no borrow is no borrow. In a generic body a `T`-typed value, and a value whose type is formed over `T`, is read under §28.1's class-or-interface assumption; the positions a value substitution re-keys are the returns §9.7's return bullet names — `owned T`, `where T: value`, and a `T`-formed return — each read at the instantiations at which the type holds borrows.

§9.7 keeps what is genuinely specific to a value: how its one source set is read and written (the first bullet, with #5714's holder rule), the no-temporary-source rule, the static null-source form (with 0151's static-storage-sourced admission, reused verbatim: `static readonly _view: Span<int> := _buf.AsSpan()` over a static buffer is admitted), and the return forms with their per-instantiation re-reading of `owned T`, `where T: value` and a `T`-formed return (the v0.326 ground, `DECLINED.md` row 194: under the class assumption an `owned T` body may return any owned production, so the value's carried borrows would be lost at the caller; `Wrap<Item>` over `Box<T>` stays rejected, `Pass<Pair>` and `Id<Pair>` stay rejected). Everything else is retired: §9.7's instance-field bullet (replaced by one sentence pointing at the field-store bullet), its borrow-erasing bullet (replaced by one stating that a box is a borrow at every position), §8.6's "exactly two positions", §12.9's and §27.1.1's and §27.6's span retypings (0156), §28.14's interface-`scoped` rejection (`DECLINED.md` row 143's bar is exactly this proposal), §30.1's two frame paragraphs (replaced by two short ones reading the value as a class borrow: held until settlement), §30.5's `Task<T>` row (0150), stdlib §6.5's payload rule (0154), stdlib §4.16's "never storable" and the `IReadOnlySpan` read-as-span machinery (the interface becomes an ordinary interface its five records implement, user implementers admitted), nine Appendix C rows (four C.6 rows become one).

**Soundness.** 0153's ground: every read of a record-carried borrow is a member access on the referenced object — a class reference is read by a member access; a span reads `Buffer[Start + i]` through its backing object's indexer; an inline array's slots are class references. After any flag-setting kill a stale read through a stored value faults deterministically in checked mode, exactly as through a stored class borrow; after a silent kill (a transfer) the object lives on under its new owner and the domain clause is the recorded obligation, exactly as for a class borrow. The one genuine static asymmetry is the return of a value whose type a substitution re-keys, kept per instantiation. Every other per-instantiation rejection of §9.7's generic paragraph is subsumed by the class rules under the assumption: `Keep<Pair>` is the field-store residual (as `Keep<Item>` is), `Bag<Pair>` is §28.11's residual (as `Bag<Item>` is).

**(a') — (a) plus one warning.** Under §28.3's *Diagnostics*:

> **The holds-borrows admission warning.** The compiler **must warn** where a value that holds borrows, carrying at least one borrow, is admitted at a position at which its carried sources are bounded by a recorded trust clause rather than statically — the positions that were compile errors for such a value through v0.333: a store into a non-`owned` instance field or property; a store into a field-held, field-reachable or escaping collection; an `async` parameter, result or local across a suspension with a caller-side source, a `Task<T>` result, an `AsyncEventSource<T>` payload; and a conversion of such a value to `Object` or an interface other than `IReadOnlySpan<TElement>` at any position but a member-call receiver or a same-body local (the last site at which any rule can see the carried borrows). The warning names the value, its carried sources, the holder, the obligation and the static remedies (store the source and re-derive; a `scoped` parameter for a boxed value; an owning holder). The program stays accepted; a value that carries no borrow draws nothing; the report mode lists the same sites.

The warning is a new default-build rule — the owner's standing preference is against adding one — and it is outside rationale §5.28's doctrine, which reserves default-build warnings for statically-certain hazards (a parameter-sourced span in a field is no more certain to dangle than `_owner: Customer`). The ground offered for the exception, recorded in §5.28 under (a'): a value type has no `scoped` spelling of its own and no reference identity, so a copy that carries a borrow into a holder is invisible to the source's owner in a way a stored reference is not; and the authors who wrote under the bans through v0.333 would otherwise lose every notice at once. ## 5. Decision (delegated ruling, 2026-10-08; drafted 2026-10-09; decided by the critic 2026-10-09)

### 5.0 Decision: **option (b)** — the compile-time bans kept, both routes closed by declaration

The owner's standing directions are weighed in their stated order.

1. **Soundness first.** Every option is sound in checked mode. What separates them is what each guarantees for the programs (a) would newly admit: under (b) a value that holds borrows is held past its bound at no position, a compile-time guarantee; under (a) and (a') the same program is accepted, a stale read through it faults in checked mode, and in an unchecked build it is undefined behaviour. That *is* the posture a class borrow already accepts at the field- and frame-held residuals (rationale §5.15's v0.332 record, `DECLINED.md` row 579, proposal 0153 §4: "no larger"), so (a) opens no hole of a new kind. It is still a weakening, from a static guarantee to a run-time one, at every field, `async`, task-result and `Object` position such a value would newly reach. The class regime accepts that weakening because the back-reference idiom needs it (rationale §5.31: a trust admission is "the taught spelling of the back-reference (Guide 01 §5)"). For spans and borrow-bearing records nothing needs it: row 579's reopening bar, "a measured program that needs a span field and that the source-field remedy does not express", is unmet. The lane's measurement (§2) and the retrospective's (R5 §6: "the bar as written is not met by a program") both find no such program. Rows 42, 653, 654 and 657 kept their declines on this same posture at v0.332, after 0153 had supplied the backstop, so 0153 does not reopen them on its own. The decisive asymmetry: under (b) a route the enumeration may still leave is, because of 0153's flag, at worst (a)'s posture at that one position. (b) is therefore never less sound than (a) at any program, including against routes not yet found. (a') changes none of this, since a warning restores no static bound.
2. **Simplicity.** (a) wins clearly: about 7,400 words and nine Appendix C rows become one bullet, and the enumeration that produced a new route at each of four matrix runs goes away. That gain is real and recorded here. It ranks below soundness in the owner's order, though, and (b)'s cost is about 400 words for three narrowings of zero measured reach. That matches the owner's standing preference: "narrow a feature when its measured reach is negligible, rather than add another rule". Of (b)'s three rules, two are such narrowings; the third (#5740's per-instantiation `as` rule) is the issue's own recommendation and 0156's posture.
3. **Reach.** (a) admits 21 rule cases, about 22 lit files and about 10 gtest programs. Every one of them is a *rejection pin*: a test written to assert the ban, not a program that needs the admission. Under (a) these pins would also lose their observable, since each becomes an accept whose only signal is the unimplemented report mode (#4605). (b) flips nothing and rejects nothing measured: the critic re-measured zero user implementers of the interface (every hit is a skipped stdlib transcription in the doc corpus), zero records that hold borrows declaring `Equals(Object?)`, zero generic records declaring it, zero user interfaces extending `IReadOnlySpan<TElement>`, and zero `as T` over a span-interface operand.
4. **The owner's question** ("can a compiler still warn about those incorrect cases?") is answered more strongly than (a') answers it: under (b) the compiler still *rejects* them.

The lane's recommendation of (a'), kept below as §5.1 for the record, is declined on point 1. ## 7. Self-critique

- **Is (a) sound where the class regime is?** The one place the class regime leans on something a value lacks is reference identity for the consume-site freeze: K5.5 already traces a span local as a live borrow of its source, so a `move xs` under a live span is frozen today, and (a) changes nothing there. A value *copy* into a holder is the residual's case, as a class reference copy is. The `owned T` asymmetry is kept per instantiation on the v0.326 ground. I found no shape where the class rule admits and the value rule must reject for soundness.
- **The static-storage-sourced span.** (a) admits `static readonly _view: Span<int> := _buf.AsSpan()` over a `static owned readonly _buf`, reading the span's borrow as sourced at the static field read (§9.7's receiver-sourced form 1 names the receiver expression as the source). 0151's text says a *method result* of a static referent is not static storage; a span over the referent itself is a borrow of the referent, which is process-lived. The edit states the admission explicitly with that example so the two sentences do not disagree; the critic should check that `l4_14_0006`'s flip is wanted.
- **(a')'s warning at `Console.WriteLine(span)`.** The conversion to an `Object` parameter is the one position where neither side can see the admission (the callee's store of an `Object` parameter is the residual whether or not the box carries borrows), so (a') warns at the caller's conversion, which makes `Console.WriteLine(span)` warn. That is noisy for a non-storing callee and is exactly "the cases (b) rejects". A narrower (a') that exempts the plain-parameter conversion would be silent on `b.Keep<Object>(span)` over a storing callee — the shape 0146 was written for — so the broad form is drafted and the narrowing is listed as a question for the critic (`W1.md`).
- **The row-7 keying of a static `IReadOnlySpan` return.** Kept by one retained sentence so that (a) rejects nothing; a purer (a) would let the static-announcement rule refuse such a return (0 exist). Recorded as a question.
- **Measured reach.** The retrospective's counts were re-derived program by program for the rule corpus (one case moved from "keeps" to "flips": `l4_14_0006`) and taken on trust for the lit hand-classification (the needle lists are in `reach_r5.out`); the implementing lane re-reads each lit file at the re-expectation.
- **What this proposal does not decide.** W2's R8 (the `Object` slot) and the hashable-row questions (RC12–RC16); whether `CancellationToken`'s A10 certification is still needed under (a) — the edits keep it as the certified statement of the general obligation, which is what it now is; whether the §5.28 exception (a') records should be reviewed at the next subtraction pass.
