## 0. Thesis

`IReadOnlySpan<TElement>` is the one reference type whose values are "read as holding borrows" (§9.7). Every rule that keys a borrow on a value's *kind* therefore carries a clause for a *reference* that stands for a value: a conversion to it is admitted as one of §8.6's "exactly **two positions**" (proposal 0146), a retyping *of* it is a borrow-erasing conversion (0156: variance at a type argument, §27.1.1's two slots, a method reference's formation), an `as` or typed pattern over it at a type parameter is a per-instantiation requirement (0159's #5740 rule), a flow-narrowing of it is read at the declared type (#5835's span face), it is closed to user implementations (0159 C1, so that "read as the span it boxes" has a finite set of boxes), and the equality search at its element type compares by box identity (#5844). A record needs none of these: a value type does not vary (§12.9), its function-type slots are invariant (§27.1.1), `v as T` over a value operand at a reference target is already rejected (§12.7), it has no implementers, and `Contains` over a record uses the record's own equality or nothing.

The interface buys two things: a parameter type that accepts any read-only span whatever its backing, and one declaration of the byte read tier (32 members) reaching four receivers. The measured price is about 2,800 normative words across the two documents, six rules, and five proposals' worth of churn (§1.2, §2). The measured use is nil outside the feature's own probes (§2). This proposal retires the interface (**F2-B**): the spans are five records and nothing else; breadth across backings is one overload per span type — the advice stdlib §4.16 itself gives for hot paths; `SequenceEqual` is declared on each span for its own type and for the read-only span of each heap backing; the byte read tier is declared twice, on the two read-only heap spans, and a writable span reads through `AsReadOnly()`. Nothing is newly admitted beyond two zero-site consequences of the interface's absence (§4.1), the borrow-flow matrix's span row collapses onto its borrow-bearing-record row (§5.4), and §8.6's two positions become one.

## 1. Ground truth

### 1.1 What the interface is, and what it is for

Stdlib §4.16 declares `IReadOnlySpan<TElement>` with `Length`, `IsEmpty`, an indexer getter, `IndexOf`, `Contains` and `SequenceEqual(other: IReadOnlySpan<TElement>)`; the five span records implement it at their indexer's type (`Span<T>` and `ReadOnlySpan<T>` at a class `T` implement `IReadOnlySpan<T?>`, every other heap span `IReadOnlySpan<T>` at its own `T`, `ReadOnlyStringSpan` `IReadOnlySpan<char>`); it is "closed to user implementations" (0159); `Slice` is deliberately not on it; the byte read tier is one `extension IReadOnlySpan<byte>` reaching the four byte spans (0123 R7, v0.290); the array family's concrete cross-mode `SequenceEqual` overloads were retired in its favour (0123 R3). Its own *Performance cost* paragraph: "Indexer access through an `IReadOnlySpan<TElement>` parameter is a virtual dispatch … For code that accesses spans in inner loops, the recommended pattern is to take the concrete span type (possibly via overloads) rather than the interface."

## 3. Options

### 3.1 F2-B — retire the interface; breadth by overloads (adopted)

The five span records implement no common interface. A member that accepts a read-only span of either heap backing declares two overloads, `(ReadOnlySpan<T>)` and `(ReadOnlyArraySpan<T>)`. `SequenceEqual` is declared on each span for its own type and ▲ for the read-only span of each heap backing, at the receiver's own `T`; a writable span as the argument converts by `.AsReadOnly()`. The byte read tier is declared on `ReadOnlySpan<byte>` (the existing block, re-headed) and ▲ on `ReadOnlyArraySpan<byte>` with the same members, name for name; `Span<byte>` and `ArraySpan<byte>` read through `AsReadOnly()`. Every interface clause in the spec is deleted; §8.6's two positions become one.

```bezel
// ▲ stdlib §4.14 (both presentations) — the read-only span of this backing and of the other
public method SequenceEqual(other: Span<T>): bool;
public method SequenceEqual(other: ReadOnlySpan<T>): bool;
public method SequenceEqual(other: ReadOnlyArraySpan<T>): bool;
// ▲ stdlib §4.15
public method SequenceEqual(other: ArraySpan<T>): bool;
public method SequenceEqual(other: ReadOnlyArraySpan<T>): bool;
public method SequenceEqual(other: ReadOnlySpan<T>): bool;
// ▲ stdlib §3.3
public pure method SequenceEqual(other: ReadOnlySpan<char>): bool;
public pure method SequenceEqual(other: ReadOnlyArraySpan<char>): bool;
// ▲ stdlib §4.15: "the §4.14 endianness-aware read tier is declared again as `extension ReadOnlyArraySpan<byte>`,
//   member for member and with identical semantics"
```

The nullability rule at a class `T`: the overloads are declared at the receiver's own `T`, so a `ReadOnlySpan<Widget>` (slots `Widget?`) compares with a `ReadOnlyArraySpan<Widget>` (slots `Widget`), `Equals` null-safe on the nullable side, a null slot equal to no element. Today's interface admitted the pairing `ReadOnlySpan<Widget>` ↔ `ReadOnlyArraySpan<Widget?>` instead (both at `IReadOnlySpan<Widget?>`) and no other cross-backing pairing at a class `T`; the measured count of class-`T` cross-backing comparisons is zero in either direction (§2), so the choice is made on the rule's shape (§3.4).

### 3.2 F2-A — the same deletions with a unified intrinsic view (declined)

One read-only view type, `ReadOnlySpan<E>`, a compiler-intrinsic positional record over a backing fixed at construction — an `OwningBuffer<T>` (then `E` is `T?` at a class `T`) or an `Array<E>` — whose indexer reads through the backing's accessor; `ReadOnlyArraySpan<T>` retired; every span's `AsReadOnly()` producing it; the byte read tier declared once on it. Two facts keep this from being the simpler package. (i) The element type must be the type argument, since one type cannot carry two indexer types by run-time backing: `OwningBuffer<Widget>.AsReadOnlySpan()` becomes `ReadOnlySpan<Widget?>` where today it is `ReadOnlySpan<Widget>` with a `Widget?` indexer — a shift at the 5 class-typed buffer spans in `tests/` and at the 101 `ReadOnlySpan<T>` sites in generic bodies at their class substitutions, and a new face of the two-presentation rule (#5790) at the type argument. (ii) `ReadOnlyStringSpan` cannot join it: the merged record is borrow-bearing, a string-backed value in it would be unstorable in fields (today's `ReadOnlyStringSpan` is an ordinary record; 4 gtest field declarations hold one, 186 hits in 33 files use it), and §3.6 rule 1 bars a holds-borrows property that depends on contents. F2-A therefore ends with three records, one new intrinsic, the same spec deletions as F2-B, and a mechanical rename at 141 gtest hits in 39 files and 69 lit/conformance hits — about five times F2-B's migration, for a unified view no measured program wants. §25.4 bars user-defined conversions, so "every span converts to it" is spelled by methods under either shape.

### 3.3 R-4 — the read tier on all four byte spans (declined)

Declare the 32 read members on `Span<byte>` and `ArraySpan<byte>` as well, so a writable span reads without `AsReadOnly()`: the 128-member state DECLINED 963 retired at v0.290, restated in one sentence. The cost is twice the declared surface for one call saved at a writable receiver; `AsReadOnly()` is a record construction with no allocation; the measured need is seven gtest rows and one rule case that read what they just wrote through the same `Span<byte>` (`sp.WriteInt32LittleEndian(…); sp.ReadInt32LittleEndian()`), which respell as `sp.AsReadOnly().ReadInt32LittleEndian()`. The owner's standing preference is simplicity; F2-B keeps the smaller surface and records the ergonomic bar (§5.3).

### 3.4 S-exact — nullability-exact cross-backing overloads at a class `T` (declined)

Declare the class-`T` presentation's cross overload as `SequenceEqual(other: ReadOnlyArraySpan<T?>)`, reproducing the interface's pairing exactly. The array side then has no spelling for the reverse pairing: `ArraySpan<Widget?>.SequenceEqual(other: ReadOnlySpan<…>)` would need a `ReadOnlySpan<Widget?>`, a type the buffer family does not form (`OwningBuffer<T>` is declared over a non-nullable class `T`). The admission would be asymmetric, it preserves an accident of the interface's invariant `TElement` rather than a rule, and no measured site needs it. The adopted rule — one overload per backing at the receiver's own `T`, compared null-safely — states in one sentence.

### 3.5 The status quo (declined)

Keep the interface and its clauses. §1.2 is the price; §2 is the use. Its own section calls its dispatch the slower path and recommends the concrete types; F2-B makes the recommended path the only path.

## 4. Evaluation

### 4.1 Soundness

F2-B admits no new route. Every position a span could reach only through the interface — an interface-typed parameter, local, return, field (already rejected), type argument, variant or function-typed retyping, `as` or typed pattern at a type parameter in a generic body, a flow-narrowed carrier — becomes a position a *record* reaches by §9.7's ordinary rules, which give the same verdict or a stricter one: a value type does not vary (§12.9: "A variant assignment whose source has a value-type type argument is rejected"), a value-typed function slot is identical-only (§27.1.1: contravariance and covariance are stated for "class or interface type" slots), `s as Object` or `s is Object` over a span is §12.7's value-operand compile error, and `s as T` at a type parameter is rejected at every reference substitution by the same paragraph ("`as` against a reference target is rejected at the instantiation site whatever the answer"). The storage bans are untouched: a `ReadOnlySpan<int>` field is rejected after F2 exactly as before, by §9.7's instance-field bullet (the span's `Buffer` is non-nullable, so no null-source form exists). The unchecked-build surface does not grow; the checked-mode posture (0153's flag-checked reads) is unchanged. The one verdict that moves in the admitting direction is a consequence of the interface's absence, not a rule: a dispatched generic `async` method whose declaring constraints are `where T: class` now establishes that its `T` parameter holds no borrows (§30.1 named `where T: class` as insufficient only because it admitted `IReadOnlySpan<TElement>`); measured sites: zero (`tests/`, `docs/`).

### 4.2 Simplicity

Six rules retired (§1.2's table); §8.6's "exactly two positions" becomes "exactly one"; §9.7 loses its interface paragraph and the retyping half of its borrow-erasing bullet; §12.9 loses a paragraph and a condition; §27.1.1, §27.4, §27.6, §12.7, §28.3, §28.14, §29.2, §29.4, §30.1, §30.5 and Appendix C lose their "or declared `IReadOnlySpan<TElement>`" clauses; stdlib §4.16 becomes a retired stub in the §3.4 shape. Net, on the edited sites: spec 2,607 → 836 words, stdlib 2,018 → 855; the code-generation reference loses the 0156 pair and the interface listing (865 → 551). Added: nine one-line overload declarations, one sentence declaring the second read-tier block, one nullability sentence, the stub, and two dated rationale paragraphs (568 words, the record of the decision).

### 4.3 Consistency

The language already states that spans are records read by the record rules; the interface was the exception every rule had to name. After F2-B the holds-borrows rules read "a value type that holds borrows" with no carve, the borrow-erasing and set-erasing twins are symmetric again (`Object` or an interface, with no third type), and the stdlib's own advice — concrete types for breadth via overloads — is the rule rather than a performance note. DECLINED 963 and 967 are reversed in part, on a stated ground that is not the one their bars named (§5.3); the records are annotated, not struck.

### 4.4 Migration (measured, §2)

**Newly rejected**: every spelling of the interface — 31 parameters, 14 locals and one field in seven gtest files; six rule cases that declare at it; one lit comment; the conf-doc transcriptions of the five records' `: IReadOnlySpan<…>` lines and of §4.16 (regenerated with the stdlib). Each is a probe of the interface itself. **Respelled, verdict kept**: two cross-mode `SequenceEqual` calls whose argument is a writable span (`rob.SequenceEqual(sb)` → `rob.SequenceEqual(sb.AsReadOnly())`), eight byte-tier reads on a writable receiver (seven gtest rows and one rule case) (`sp.ReadInt32LittleEndian()` → `sp.AsReadOnly().ReadInt32LittleEndian()`), four `SequenceEqual` calls whose argument was an interface-typed local (`var sp := b.AsReadOnlySpan();` then the new `(ReadOnlyArraySpan<T>)` overload). **Unchanged**: 24 byte-tier reads on read-only receivers, 856 `AsSpan`/`AsReadOnlySpan` calls, `l4_16_0001`'s `bufSpan.SequenceEqual(arrSpan)` (the new cross-backing overload resolves it). **Newly admitted**: the `where T: class` case above (zero sites); a class-`T` buffer span compared with a non-nullable array span (zero sites). **Newly rejected without a direct respelling**: a class-`T` buffer span compared with an `Array<T?>`-backed span (zero sites; neither side's overloads spell the pairing — compare element by element in a loop, or copy into one backing); a buffer or array span compared with a `ReadOnlyStringSpan` as the *argument* (zero sites; the string span's own `SequenceEqual` takes either).

## 5. Decision (delegated ruling, 2026-10-08; decided 2026-10-13)

### 5.0 Decision: **F2-B** — the interface is retired

The five span records implement no common interface and are read by every rule as the records they are. A member over either heap backing declares `(ReadOnlySpan<T>)` and `(ReadOnlyArraySpan<T>)`. `SequenceEqual` is declared on each span for its own type and for the read-only span of each heap backing, at the receiver's own `T`, null-safe; a writable argument converts by `.AsReadOnly()`. The byte read tier is declared on `ReadOnlySpan<byte>` and, member for member, on `ReadOnlyArraySpan<byte>`; a writable byte span reads through `AsReadOnly()`. §8.6: a value that holds borrows converts to `Object` or an interface at exactly one position, the receiver of a member call. Stdlib §4.16 is retained as a retired stub (the §3.4 precedent), its anchors kept so dated citations resolve.

### 5.1 The §10 subtraction review

Process §10 asks of the shipped surface *what is no longer earning its place*, with "a construct's keep defended, not assumed". The defence of the interface is its two purchases (§1.1). Breadth across backings: the tree contains no member that needs it (§2: every interface-typed parameter is a probe), and the stdlib itself declares none (`Stream.Write`/`File.WriteAllBytes` take `(Array<byte>)` and `(ReadOnlySpan<byte>)`; DECLINED's deferral row). The one-block read tier: a declaration economy of 32 lines, bought with ≈2,800 normative words and the rules of §1.2. Neither purchase defends the keep.
