*Added 2026-11-02, from R38. The R38 producer briefs restated `lane-contract.md`'s standing rules
in every brief — the same problem the peer and harvest templates already solved for their lanes.
This file is the committed copy of the slots, so the next run's brief carries only what is
specific to its assignment.*

Copy this file, fill every slot, and dispatch it as the lane's brief. **Do not restate a standing
rule here** — `CLAUDE.md` and `docs/ops/lane-contract.md` hold them, and the lane reads both before
its first command. If this run overrides a standing rule, say so explicitly under *Run overrides*.

  take where the spec is ambiguous.
- **The remedy.** What to change, and where (`file:line`).
- **The deliverable.** The regression test's shape and the rows it must pin by name.

## The brief does NOT restate

These are in `CLAUDE.md` / `lane-contract.md` and the lane has read them:

- the build/test command and the `--area` / `--probe` forms, and "never the full suite";
- rebuild the **test binary**, not just `bezelc`;
- never `git stash`, never `git add -A`, never `git config user.*`, never two `cmake --build` on
  one build dir;
- fail-without proven mechanically per row (copy → `git checkout <base> -- <files>` → red →
  restore → green), and `git status --short` clean at the end;
- the subject form `fix #N: <what> (§X.Y, vN)`, one commit per issue, the `narrow` / `test` /
  `fix-forward` variants, and that a subject naming an issue CLOSES it;
- the exactly-one-trailer rule and the forbidden second trailer;
- never weaken a test oracle, and name every flipped test in the commit body;
- the 19a matrix (what ELSE the change does) and the 19b sweep of embedded test programs;
- the spec-question / spec-defect filing rule for an ambiguous or self-contradictory spec;
- the handback fields.

**State them once, in a line, if a lane is likely to get one wrong.** Otherwise point and move on.

## The handback

`lane-contract.md` §21 lists the fields. This brief adds only the run-specific ones:

- the reviewer's report path and the rejected commit's SHA, if this is a fix-forward — and a
  **per-finding disposition**: what was done, with `file:line`, for EVERY finding the reviewer
  raised (a note is not a finding to close, and an unaddressed finding is a REJECT);
- the **issue numbers filed** by this lane (deferrals, newly-discovered bugs, and any split the
  coordinator decided on);
- the **matrix result** (19a) as a table of program → base verdict → tip verdict;
- the **fail-without / pass-with** counts per row, as the gtest line from the log;
- the probe directory's path (the coordinator harvests accepted probes into the corpus).

## Why this template exists

The R38 briefs averaged ~3,000 words each, and most of it was `lane-contract.md` restated — the
same failure the peer and harvest templates had already fixed for their lanes. The cost is not
just tokens: a brief that restates a rule is a brief that can **restate it wrongly**, and the
reviewer's §5 behaviour-flip grep is then checking against a brief the reviewer never read.

One more cost, measured in R38: a brief that inlines the standing rules grows to the point where
the run-specific part — the one thing the lane cannot get from the contract — is the smallest
share of it. The assignment, the hot files, and the findings are what the lane actually needs.
