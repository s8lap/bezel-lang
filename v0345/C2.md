## #6764 — `GetType` and `ReferenceEquals` on records, enums, choices and interfaces (with #6595)

**Decision.** Reserve both names on every value kind, at every member kind and every parameter list — a method, static or instance, a field, a property, a `const`, an enum constant, a choice case or a nested type — as §12.2 blocks them on a class, with no admitted spelling (unlike the three virtual names, which admit an instance method at another parameter list). An interface declares no member of either name, instance or static (§11.8): a class cannot declare one (§12.2) and a value kind cannot (§9.2), so no type could implement it. The static class carve-out (§11.7: `GetType` free, `ReferenceEquals` blocked) is unchanged — a static class has no instances and is not a value kind.

**Class and why.** Ruling. No sentence admits the declarations: §12.2's clause is worded for a derived class, §9.2's reservation names "the three names", §11.2 is silent. Both readings fit the text (the triage and its critic agree), so deciding it is a ruling; v0.339 landed the three-name reservation on value kinds (#6191, #6305) on the same footing. The ground: `v.GetType()` is defined for every value (§8.2) and answered from the static type, so a record's own `GetType()` would mean one thing at `r.GetType()` and another through the box — the confusion §12.2 exists to prevent; a static `ReferenceEquals` on a value kind reads as `Object.ReferenceEquals` and is not. On an interface the member is unimplementable, so admitting it only defers the error to every implementer. Choice cases are named because §35.1 counts a case as a member for the name-collision rule and `Opt.GetType(x)` would read as a call of `Object`'s surface.
