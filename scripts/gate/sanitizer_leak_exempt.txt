# sanitizer_leak_exempt.txt — tests whose generated-code sanitizer LEAK
# report is a DELIBERATE assertion, not a defect (#4537).
#
# Read by scripts/gate/sanitizer.py. Format: one `suite.name` per line, with
# the reason after a `#`. Blank lines and full-line comments are ignored; a
# MISSING file is an empty set, so losing this file makes the gate stricter,
# never looser.
#
# ── STATUS FIELD (#4557) ────────────────────────────────────────────────────
# This file had quietly become the project's only record of a set of known,
# unfixed leaks with no owner: measured 2026-09-21, 19 of then-38 rows cited
# no issue at all, and of 15 distinct issues cited, 13 were CLOSED — rows
# whose fix landed on the CENTRAL case but left a residual axis leaking, with
# the residual axis's own tracker lost when the issue closed. See #4557.
#
# Every data row's reason therefore starts with a REQUIRED `status:` token,
# one of three values, read (and gate-enforced, scripts/check_leak_exempt_
# status.py) as the leading word(s) right after the `#`:
#
#   status:trade    — a DELIBERATE, permanent boundary: the leak is the safe
#                      side of leak-vs-crash/leak-vs-UAF, a proof-soundness
#                      control ("stays rejected", "not armed", "boundary/
#                      negative control"), or a spec-mandated exclusion. No
#                      `issue:` required — the row's own prose is the record.
#   status:residue   — scoped OUT of an already-landed fix, a fix is still
#                       owed, tracked by its OWN issue (which may differ from
#                       the issue the row's prose otherwise mentions, e.g. the
#                       fix issue that closed leaving this residue behind).
#                       REQUIRES `issue:NNNN` naming that OPEN tracker.
#   status:defect    — a leak nobody has scoped out on purpose; a fix is
#                       owed and no residue tracker exists yet for it.
#                       REQUIRES `issue:NNNN` naming that OPEN tracker.
#
# `issue:NNNN` is a single open-vs-closed source of truth per row — it is
# deliberately NOT re-derived from every `#NNNN` mentioned in the free-text
# reason, several of which are typically present (the fix that produced the
# control, a sibling issue, etc.) and are not all open trackers of THIS leak.
#
# check_leak_exempt_status.py enforces the STRUCTURE (every row has a valid
# status; defect/residue rows have a well-formed issue:) at every gate, fully
# offline. Enforcing the OPEN/CLOSED state of a cited issue needs GitHub, and
# the gate is deliberately hermetic (no network call in gate_full_cycle.sh
# anywhere) — so that half is a SEPARATE, explicitly-manual companion,
# scripts/check_leak_exempt_issue_state.sh (same non-gated-audit shape as the
# pre-existing scripts/check_issue_refs.sh), which is what actually catches a
# defect/residue row whose tracker has since closed. Run it periodically; it
# is not part of scripts/ratchet_sweep.sh by design.
#
# THIS IS THE LEAK SIBLING OF sanitizer_exempt.txt, WITH A DIFFERENT
# RATIONALE — read that file first. sanitizer_exempt.txt declares rows whose
# CORRUPTION is undefined behaviour the spec itself allows; that reasoning
# does not apply here. Every row below deliberately ASSERTS that a real
# allocation escapes the compiler's release path — the test is checking for
# the ABSENCE of a fix, on purpose, because the underlying defect (e.g. a
# missing release site for a nested record/string field) is tracked by its
# own issue and not yet fixed. Under `--full` the deliberately-leaked
# allocation makes LeakSanitizer report at process exit, and the row PASSES
# because passing is exactly what "the leak is still there" looks like.
#
# WHAT BELONGS HERE — a row that POSITIVELY asserts a leak occurred (checks
# for the PRESENCE of "detected memory leaks" / `ERROR: LeakSanitizer` in the
# diagnostic text, or an `r.ran == false` outcome it explicitly attributes to
# a leak headline rather than a crash). If a row's leak is incidental (it
# would pass whether or not LSan happened to see the allocation) it does not
# belong here — fix the row instead, or drop it to sanitizer_exempt.txt if
# what it actually pins is a UB corruption crash.
#
# WHAT DOES NOT — a row asserting leak-FREEDOM (`find(...) == npos`,
# `ASSERT_FALSE(leaksAtLeast(...))`, `expectLeakFree`, `hasSanitizerReport`/
# `hasMemoryError` used with `EXPECT_FALSE`) never produces a report while
# passing, so it needs no declaration; and a row whose own runner redirects
# its subprocess output away entirely (`> /dev/null`, outside the standard
# aot_support.hpp harness) is structurally invisible to this channel and also
# needs none.
#
# A leak report in a FAILING test is never exempt (this file is consulted
# only for tests that PASSED), and a report from a test not listed here fails
# the cycle by name — same rule as sanitizer_exempt.txt, applied to leaks by
# scripts/gate/sanitizer.py's verdict().
#
