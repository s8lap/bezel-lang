# sanitizer_exempt.txt — tests whose generated-code sanitizer CORRUPTION report
# is the SPECIFIED outcome, not a defect (#4533).
#
# This file is CORRUPTION only. For a deliberate LEAK assertion
# (`leaksAtLeast`), see the sibling file sanitizer_leak_exempt.txt (#4537) —
# a different rationale (an on-purpose assertion, not a UB allowance), so a
# separate list rather than one file conflating the two.
#
# Read by scripts/gate/sanitizer.py. Format: one `suite.name` per line, with
# the reason after a `#`. Blank lines and full-line comments are ignored; a
# MISSING file is an empty set, so losing this file makes the gate stricter,
# never looser.
#
# WHAT BELONGS HERE — and it is a short list by construction:
#   a row that runs a program whose behaviour the SPEC LEAVES UNDEFINED, and
#   whose oracle therefore asserts nothing about the crash. Generated-code
#   AddressSanitizer exists to detect exactly that read, so its report is the
#   CORRECT outcome there, not a false positive.
#
# WHAT DOES NOT — a report in a row that merely tolerates it. Every entry is a
# claim that the spec defines no observable to assert; if a row could assert
# one, fix the row instead. A corruption report in a FAILING test is never
# exempt: the list is consulted only for tests that PASSED.
#
# PRECEDENT, and the reason this file is short. When the same question came up
# for §31.1 (tests/codegen/throw_borrow_field_catch_dispose_1678_test.cpp), the
# project's answer was to DELETE the cell, not to exempt it:
#
#   "Asserting that undefined behaviour 'runs to completion' under a sanitizer
#    whose whole job is to detect it is a contradiction, and the ASan report is
#    the CORRECT outcome, not a false positive."
#
# tests/codegen/checked_disposal_621_test.cpp made the same call by omitting
# unchecked-mode use-after-dispose rows outright. Prefer those over an entry
# here; an entry is for a row whose non-UB half is not already pinned elsewhere.
